The resume problem

Health Connect has no push. Your first read is often 0.

Samsung Health, Fitbit, and Google Fit sync in the background. When your app comes to the foreground, the first read usually returns before they finish. The polling helpers keep trying until ready passes, then report whether the result is real.

  • Polls on mount and on every AppState resume
  • satisfied: false means the timeout hit, so it may be a real zero
  • Non-React: pollOnForeground, pollUntil, waitUntil
TodaySteps.tsx
import {
  readSteps,
  timeRangeToday,
  useForegroundPoll,
} from '@solutionforest/android-health-connect';

export function TodaySteps() {
  const { value, satisfied, loading } = useForegroundPoll(
    () => readSteps({ timeRangeFilter: timeRangeToday() }),
    {
      ready: (r) => r.records.length > 0,
      timeoutMs: 15_000,
    },
  );
  // satisfied === false → timed out; may be a real 0
}
